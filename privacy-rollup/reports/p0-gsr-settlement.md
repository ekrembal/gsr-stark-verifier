# P0: a zero-knowledge settlement mined on the optimized `gsr` node

`tools/batcher_e2e.py` run against `bitcoin/` = `jmoik/bitcoin` branch `gsr` @ `ad6c16ff` (built with
`-DENABLE_IPC=OFF`), regtest with `-vbparams=tapleaf_0xc2:0:3999999999`. The rollup leaf is the compressed
(`OP_MACRO`/`OP_CALLMACRO`) covenant generated by `pr-batcher init` for the current `apply_batch` image and
control root. Raw report: [`p0-gsr-batcher-e2e.json`](p0-gsr-batcher-e2e.json). 8 vCPU, AVX-512 CPU prover
(`GSR_BUILD_CPU_BATCH=1`, 16 lanes).

| | measured |
|---|---:|
| covenant generation (`pr-batcher init`) | 61.5 s |
| user deposit proof (SDK, 3 segments, `identity_zk`) | 350.7 s, 276,241 B receipt |
| settlement proof, 1 join-split (15 segments, lift/join, `resolve_zk`, padded-SHA identity) | 1,860.5 s wall |
| of which segment proving / lift+join / `resolve_zk` / padded-SHA identity | 1,398.9 / 311.6 / 10.8 / 7.4 s |
| settlement guest cycles (total / user) | 14,942,208 / 14,059,511 |
| settlement transaction weight | **334,460 WU** |
| annex | 2,743 B |
| inputs / outputs | 2 (rollup, funding) / 1 (successor) |

The earlier figure for this row, ≈334,400 WU, was an estimate (gsr-full settlement with the compressed leaf swapped
in); the measured value is 60 WU above it. Compared with the 392,001 WU gsr-full settlement the compressed leaf saves
57,541 WU.

Also checked in the same run: duplicate submission (409 `NullifierReserved`), corrupted receipt, non-hex body,
oversized body and unknown batch are rejected; the wallet scan finds the deposited note (19,300 sats); the batcher
state survives a restart; resubmitting the settled transaction is rejected.

Not measured here: an empty settlement and multi-join-split batches on `gsr` (P1, `tools/flows_e2e.py`).
Funding still uses regtest `P2WSH(OP_TRUE)` coins, which are not safe on a public network (replaced in P2b).
